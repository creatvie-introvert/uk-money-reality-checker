## H. Milestone 2/3 modelling and consumer requirements

The future engine must load evidence through category-specific validation and explicit applicability/period checks. It must return an unavailable/unresolved result when required evidence or applicability is absent. It must not treat a successful selected-source release as a complete city budget.

Required later work includes tax jurisdiction/pay-period/category selection; council authority/band and household adjustments; rent geography/measure selection; reviewed energy postcode-region linkage and household consumption methodology; provider/regime/address selection and water billing logic; approved spending category membership and household methodology; and transport product eligibility, usage assumptions and any separately approved optimization. Reference means input evidence, not permission to use national averages as city fallback.

## I. Nonblocking ingestion and schema debt

1. **One controlled row → one record remains intentional.** Council-tax extraction unpivots band cells; rent extracts individual measure cells; NEED expands selected profiles into fuel/statistic observations. Source cell/row lineage survives. No framework expansion is needed for current adapters. Future one-to-many adapters must distinguish physical source rows, selected cells and emitted records.
2. **Zod transform escape fixed.** No current production row schema has a custom transform, so the prior unguarded safeParse was latent framework risk. Exceptions are now isolated as SOURCE_PARSE_FAILURE per row; later rows continue and accepted/rejected accounting reconciles. Normalize/output-schema exceptions were already caught.
3. Reports expose input/accepted/rejected counts and emitted records as records.length, not a separate emittedRecords field. Global inventory now reports emitted counts explicitly. All 1,191 selected input rows are accepted with zero rejection/loss. ONS spending reconciles 433 examined = 53 selected + 380 excluded; Defra 355 = 32 + 323. NEED's 100 selected profiles yield 784 applicable observations. Wider workbook rows are intentionally outside selection, not dropped selected evidence.
4. Legacy general record/geography objects are permissive and some provenance fields optional; newer category objects are strict. Generic artifact parsing is a format/status gate, not full source-fidelity validation. Exact source validation is strongest in the later water/energy/spending/transport gates; tax/rent/council gates also rely on reviewed extracts and pinned regression values. Milestone 2 must not expose generic parsing as an unqualified evidence loader.
5. Different schemaVersion values identify historical slices (1.1–1.7), and source categories versus record categories differ. No forced migration or enum/geography flattening was performed. Period fields appropriately differ by source semantics. A later loader should dispatch explicitly by category/version.
6. Source catalogue family metadata and per-page transport provenance are distinct, and catalogue governance is not release authorization. Snapshot metadata is in reports/controlled files rather than a single universal registry. Supporting snapshots are in QA/source-selection metadata; manifests enumerate primary record snapshots.
7. Python council-tax extraction has positional paths and no --check option; full pre/post-byte comparison covers it. Other source-file extractors require captures outside Git. Tax/NI and browser-only provider rows are reviewed transcriptions, not independently repeatable upstream downloads. Offline data:verify verifies pinned evidence, not source freshness or capture authenticity.
8. Generation commands run sequentially and can leave earlier families regenerated if a later family fails. They exit nonzero; data:verify is read-only and catches drift. No new build system or dependency was added.
